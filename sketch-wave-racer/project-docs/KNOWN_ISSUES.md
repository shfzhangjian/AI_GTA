## 用户反馈修复（Phase 1 期间，2025-09-23）

**用户报告：「WSDA 没反应，海面没有起伏」**
用本地 Chrome headless（CDP 驱动，`tools/e2e.mjs`）真实复现，根因两层：

1. **产品 bug（主因）**：`main.js` 以已删除的 id `hud-speed` 取 HUD 元素得到 `null`，
   主循环首帧 `speedEl.style` 抛 `TypeError` → 整个 rAF 循环终止 → 动画静止（水面冻住）
   且 `window.SWR` 从未赋值（输入看似完全失效）。
   修复：HUD 元素改为正确 id + 空值防御；新增 window `error`/`unhandledrejection`
   兜底横幅，今后此类崩溃页面直接可见，不再静默冻死。
2. **环境因素（用户端可能同样存在）**：旧版页面（未刷新）+ WebGL 软渲染回退时帧率
   很低（本项目截图机 35 FPS），观感近似"卡死"。若修复后仍感觉迟滞：请用真实 GPU
   浏览器硬刷新（Cmd+Shift+R）并在 chrome://gpu 确认 WebGL 启用。

验证：E2E 真实按键 W 2.5s → speed 0→16 / 位移 21.6m / HUD "58 km/h"；A 1.2s →
heading Δ≈1.4 rad / lateral≈1.35；零 JS 错误。截图见 `shots/phase1-e2e-driving.png`。
